## 2. FIX 2 — training-time push curriculum (`src/solo/curriculum.py`)

`TASKS['balance']` now carries a `PushCurriculum` (env exposes
`env.push_curriculum`, `env.set_push_schedule`; the trainer installs a fresh
schedule before every episode reset via `_apply_push_curriculum`).  Exact
schedule (deterministic per episode seed):

| knob | value |
|---|---|
| no pushes before | `start_steps = 20 000` |
| ramp | `warmup_steps = 400 000` (`p = clip((steps-start)/warmup, 0, 1)`) |
| magnitudes unlocked | first `1 + round(p*5)` of `(2, 4, 6, 8, 10, 12)` N*s |
| directions unlocked | first `1 + round(p*7)` of 8 evenly spaced world yaws |
| pushes per episode | 1, becoming 2 once `p >= 0.5` (`gap = 1.5 s` jittered ±10 %) |
| application height | fixed 0.95 m (chest) — height variation stays an evaluation axis |
| seed stream | `curriculum.seed * 1_000_003 + episode_seed` (distinct from the eval battery's seed) |

**Why it stays inside the held-out boundary:** every training impulse is
`<= TRAIN_MAX_IMPULSE = 12 N*s` (asserted at construction and in
`test_push_curriculum_ramp_and_held_out_boundary`), while the gate's held-out
magnitudes are 16/20/25 N*s (>12, labelled `_heldout`); 16+ N*s is beyond the
~13 N*s analytic non-stepping ceiling.  The evaluation battery
(`eval.battery_pushes`) is untouched — it is the evaluation, never the training
signal.  The trainer flags are `--push-curriculum {on,off}`,
`--push-start-steps`, `--push-warmup-steps`.

## 5. Decision and next single change

Per the stop rule ("entropy still rising **or** mean_upright still near zero at
800k -> STOP"): entropy is fixed (peaks at ~280k then falls; the run also shows
`mean_return_50` improving from ~-105 to ~-85), but `mean_upright = 0.0415` at
1.1M is still essentially zero -> **the run was stopped** (SIGINT at 1,101,824
steps; saved, exit code 0).  **The single change (entropy 0.01 -> 0.001) was
insufficient**: the policy still dodges the one-off -100 termination penalty by
collapsing into a non-terminating limb-supported pose (fall rate looks good --
0.042 with 0.000 on held-out -- while uprightness is 0.04).

**Next single change (implemented, not yet trained): `--alive-weight`**, the
weight of the positive survival term.  Measured hand-check with
`--alive-weight 10`: an upright step is worth **+10.0** and a collapsed step
**-0.05** (gap 10.05/step) while the termination penalty stays -100 (= 10 s of
standing), so collapsing is unprofitable and the gradient toward standing
dominates the entropy noise; the `alive > sum(per-step penalties)` invariant
still holds (10 > 1.65).  Ready-to-run command for the next attempt:

```
MUJOCO_GL=egl .venv/bin/python -m src.solo.train --task balance --steps 2000000 \
    --rollout-steps 2048 --gamma 0.995 --entropy-coef 0.001 --alive-weight 10 \
    --out checkpoints/solo/t1_balance_v3.pt --save-every 100000 --lock off
```

Downstream hooks this run validated: the push curriculum feeds real training
pushes without leaking held-out magnitudes, the trainer survives SIGINT and
resumes, and the monitor subcommand evaluates a live checkpoint against the
frozen baseline table end to end.
