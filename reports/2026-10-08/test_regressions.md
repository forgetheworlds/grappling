# Test regressions — diagnosis and resolution (2026-10-08)

`pytest tests/ -q` was **7 failed, 168 passed** on entry → **175 passed, 0 failed**
after the changes below. No assertion threshold was relaxed and no property was
deleted. Two root causes, both data/provenance fallout from the overnight
`STAND_UP.npz` rebuild (commit `3a7ce45`, 06:24).

Owner files touched: `tests/test_wrestling.py`, and the scorer's *generated*
calibration `data/scorer_calibration.json` (regenerated by
`scripts/calibrate_scorer.py --write`; see scope note at the end).

## A. Scorer — 6 failures, all STAND_UP-only

`test_every_reference_scores_high_on_its_own_trace`,
`test_own_trace_beats_every_cross_score`,
`test_calibration_file_matches_the_fitting_rule`,
`test_joint_noise_monotonically_reduces_score`,
`test_root_tilt_monotonically_reduces_score`,
`test_phase_shift_monotonically_reduces_score`.

### Root cause: the on-disk calibration is stale for STAND_UP — not a scorer bug, not a degenerate reference

`data/scorer_calibration.json` was generated at **03:30**; `data/refs/STAND_UP.npz`
was replaced at **06:24** (215181 B airborne montage → 115176 B grounded
shared-node chain, `git show --stat 3a7ce45`). The calibration was therefore
fitted from the *old* reference and never re-fitted.

Evidence (re-ran the documented fitting rule, `src/scorer/calibration.py`):

* Refitting from `data/refs/STAND_UP.airborne.npz` reproduces the on-disk
  STAND_UP params **22/22 exactly** (atol 1e-4) — the file *is* the airborne fit.
* Refitting from the current `data/refs/STAND_UP.npz` changes **exactly 22
  STAND_UP params and nothing else** (all other techniques byte-identical).
* `test_calibration_file_matches_the_fitting_rule` failed on the first mismatch:
  `('STAND_UP', 0, 'knee_z_s', 'at_most')` file `[0.2623, 0.4275]` vs refit
  `[0.0543, 0.1645]`.

The new reference is **not** degenerate (the re-calibrated scorer sees real
movement): per-phase means of `knee_z_s` are `0.040 → 0.036 → 0.091 → 0.343`
and `pitch_s` `0.845 → 0.649 → -1.009 → 1.068` across the four bands — a rise
from low knees to a standing clinch, exactly the `DOWN/STAND1/STAND2/CLINCH`
semantics. The property machinery is sound; only the fitted numbers were stale.

### Change: regenerate the calibration (documented workflow)

`.venv/bin/python scripts/calibrate_scorer.py --write` → only STAND_UP's 22
params change; the script's own acceptance reports min per-phase self-conformity
`0.971` (SPRAWL) ≥ 0.8 and `DOUBLE_LEG`-as-`SINGLE_LEG` `0.464` < 0.5.

Property curves, STAND_UP, stale → regenerated (`tests/test_scorer.py` helpers):

| probe | stale | regenerated |
|---|---|---|
| own-trace mean / worst phase | 0.569 / 0.459 | **0.995 / 0.990** |
| joint noise (σ 0→0.4) | 0.569→0.520 (drop .049) | **0.995→0.750 (drop .245)** |
| root tilt (0→0.8 rad) | 0.569→0.572→0.496 (non-monotone) | **0.995→0.484 (monotone)** |
| phase shift (0→0.5) | 0.569→0.528→0.536 (non-monotone) | **0.995→0.848 (monotone)** |
| self vs best cross | 0.569 vs 0.602 | **0.995 vs ≤0.795** |

All 19 scorer tests pass; every other technique's curves are monotone too.

### Why this is a fix, not a weakened test

Nothing in `src/scorer/**` or `tests/test_scorer.py` changed: no threshold, no
tolerance, no reference, no property. The failures were stale *generated data*
that must track the references (the file's own `meta.refs_sha256` records which
references it was fitted against). Re-fitting makes every assertion pass **at
full strength**; the tests' discrimination (diagonal dominance, monotonic decay)
is demonstrated above on the new reference.

### Residual (not a test failure, outside ownership)

`scripts/calibrate_scorer.py` now prints 3 band-provenance PROBLEMs for STAND_UP
(band starts 2.00/3.96/6.94 s vs reconstructed keyframes 2.05/3.90/6.83 s).
Cause: the rebuilt meta dropped `time_stretch_requested` (now `None`) while
`src/retarget/techniques.build_technique_targets("STAND_UP")` still models the
old 16-keyframe/`t952,t1110,t1125` schedule; the new chain is
`t1125→t380→t540` with 11 keyframes. Deviation ≤ 0.114 s. It does **not** affect
the scorer tests (they place phases by progress fraction, `phase_at_frac`), and
the resulting bands remain discriminative (phase-shift drop 0.995→0.848).
Re-deriving the bands would need the new chain's keyframe schedule
(`src/retarget/**` + reference meta) — not in this ticket's ownership.

## B. Backdet — 1 failure

`test_backdet_limb_contact_side_infixed_bodies`.

### Root cause: stale hardcoded side, not a resolution bug

The test was written at 03:53 (`56881ee`) against the then-current airborne
reference and hardcoded `a_left_wrist_yaw_link` at STAND_UP frame 6
(`tests/test_wrestling.py:497`). At 06:24 (`3a7ce45`) the reference was rebuilt
grounded, and the ground-start pose plants the **right** wrist.

Evidence (fresh FK on the reference traces):

* airborne frame 6: floor bodies incl. `a_left_wrist_yaw_link`, `b_left_knee_link` (old expectation).
* new frame 6: floor bodies incl. `a_right_wrist_yaw_link`, `b_left_knee_link` — no left wrist.

`body_maps` resolution is correct and symmetric: the test's own loop above the
assertion already requires `len(limb_names) == 2 * len(LIMB_BODIES)` (8 bodies,
both sides/robots, all suffix-matched), and `back_features(...).limb_contact` is
`True` for both robots at frame 6. The regression this test guards (prefix
concatenation `a_knee_link` never matching side-infixed names) is intact.

### Change: deliberate expectation update with provenance comment

`tests/test_wrestling.py` frame-6 block now requires *a resolved executor wrist*
(`a_*_wrist_yaw_link`) plus `b_left_knee_link` on the mat, with a comment naming
the rebuild and the flipped side.

### Why this is a fix, not a weakened test

The assertion is not relaxed — it still requires a named, side-infixed,
executor wrist body to be in floor contact (the exact regression it guards), and
both sides are already pinned by the resolution loop above. It only stops
hardcoding a side that the reference rebuild legitimately changed, so a mirrored
rebuild can't masquerade as a detector failure.
