# T1 v5 — residual action double-mapping bug: fix, tests, relaunch

**Agent:** SoloEnv · **Date:** 2026-10-08 · **Service:** `solo-t1-v5` (pid 3196830, live)
**Tests:** `pytest tests/test_solo.py` -> **36 passed**.

## 1. The bug (confirmed, with the arithmetic)

Two interacting lines:

* `src/solo/env.py` `step()` -> `resolve_action(action)`; in residual mode
  `ctrl = clip(base + residual_scale * tanh(action))`.
* `src/solo/train.py` `collect()` -> `ctrl = self.env.ctrl_from_unit(unit)`, where
  `ctrl_from_unit(u) = mid + half * u`.

Net: `ctrl = base + 0.5 * tanh(mid + half*unit)`.  At `unit = 0` that is
`base + 0.5*tanh(mid)`, i.e. an offset that depends on how far each joint's
ctrlrange midpoint sits from 0.  Knee joint (ctrlrange [-0.087267, 2.8798]):
`mid = 1.3963` -> `0.5*tanh(1.3963) = 0.4423 rad` of unwanted offset; elbow
(mid 1.2800) -> +0.4286 rad.  So an untrained "residual" policy did **not** start
as the stand controller and every v4 read would have been misattributed.

**Second, distinct half of the bug found by the new test:** `SoloTrainer` never
propagated `action_mode` into `SoloEnv`, so `--action-mode residual` trained an
*absolute* env: the first step differed from `_base_action` by **1.3959 rad**
(the knee midpoint) — measured by the new startup check.

## 2. The fix (one mode-aware place, plus callers)

* `SoloEnv.ctrl_from_policy(unit)` — the only supported unit->action conversion.
  `absolute`: `mid + half*unit` (clipped).  `residual`: returns the unit itself,
  because `step` applies `base + scale*tanh(.)`; therefore `unit = 0` gives
  **exactly** `base`.  Documented choice: the residual `z` is the policy's
  *already-tanh'd* unit (residual range `+/- scale*tanh(1) ~= +/- 0.38 rad`).
* `SoloEnv.action_from_ctrl(ctrl)` — inverse mapping for scripted controllers
  that emit absolute joint targets (`z = atanh(clip((ctrl-base)/scale))`), so
  StandHold/FallForward/Squat behave identically in both modes and baselines are
  never conflated with policies.
* `SoloTrainer` uses `env.ctrl_from_policy(unit)` and now propagates
  `action_mode`/`residual_scale` into `SoloEnv`.
* `RandomInitPolicyController`/`PolicyController` use `env.ctrl_from_policy`;
  scripted controllers use `env.action_from_ctrl`.
* **Evaluation/monitor path**: `train.resolve_action_mode(ckpt, cli)` resolves
  `(action_mode, residual_scale)` from the checkpoint's own config
  (`config.train`), refuses to evaluate when the field is missing and no CLI
  value was given ("refusing to evaluate through a guessed mapping"), and allows
  an explicit CLI override.  `scripts/solo_env_smoke.py monitor` prints the
  resolved mode and builds the env with it (`env_kwargs`), so a residual-trained
  policy is gated through the residual mapping.
